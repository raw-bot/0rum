The class has one public method:

class RegimeDetector:
    async def detect(self, candles: list) -> MarketRegime:

`candles` is a list of Candle ORM objects (H1 timeframe, oldest→newest order, at least 200 rows expected). Returns a `MarketRegime` Pydantic object.

**Internal helpers (private methods on the class):**

`_calculate_atr(candles: list, period: int = 14) -> float`
- True Range for each candle: `max(high-low, abs(high-prev_close), abs(low-prev_close))`
- ATR = simple mean of the last `period` True Range values
- Return 0.0 if fewer than `period+1` candles

`_calculate_adx(candles: list, period: int = 14) -> float`
- Compute +DM, -DM, TR for each candle
- Smooth using Wilder's EMA (alpha = 1/period)
- ADX = 100 × EMA(abs(+DI - -DI) / (+DI + -DI)) over `period` bars
- Return 0.0 if fewer than `period*2` candles
- Do NOT use any external indicator library — pure numpy is fine

`_calculate_atr_percentile(candles: list, period: int = 14, lookback: int = 100) -> float`
- Compute ATR(14) for each of the last `lookback` windows
- Return the percentile rank (0.0–1.0) of the most recent ATR value among those `lookback` values
- Use `numpy.percentileofscore(historical_atrs, current_atr) / 100.0`
- Return 0.5 if insufficient data

`_calculate_ema(values: list[float], period: int) -> float`
- Standard EMA: seed with SMA(period), then apply alpha=2/(period+1)
- Return 0.0 if fewer than `period` values

**Regime classification logic (CLAUDE.md §11.4 — exact rules):**

```python
# 1. Compute inputs
atr_value = self._calculate_atr(candles)
atr_pctile = self._calculate_atr_percentile(candles)
adx_value = self._calculate_adx(candles)

closes = [float(c.close) for c in candles]
ema50 = self._calculate_ema(closes, 50)
ema200 = self._calculate_ema(closes, 200)

# 2. HIGH_VOL overrides all others
if atr_pctile >= 0.90:
    regime = MarketRegimeType.HIGH_VOL

# 3. TRENDING_UP: ADX > 25 AND EMA50 > EMA200
elif adx_value > 25 and ema50 > ema200:
    regime = MarketRegimeType.TRENDING_UP

# 4. TRENDING_DOWN: ADX > 25 AND EMA50 < EMA200
elif adx_value > 25 and ema50 < ema200:
    regime = MarketRegimeType.TRENDING_DOWN

# 5. Default: RANGING (ADX <= 25 OR ATR < 50th percentile)
else:
    regime = MarketRegimeType.RANGING
```

**`src/pipeline/dedup.py`**

Module-level logger: `log = structlog.get_logger(__name__)`

```python
def dedup_signals(
    signals: list[CandidateSignal],
    cooldown_minutes: int = 60,
) -> tuple[list[CandidateSignal], list[CandidateSignal]]:
```

Returns `(survivors, deduped)` where `survivors` are signals that passed dedup and `deduped` are the ones flagged.

Algorithm:
1. Sort `signals` by a stable key — use the original list order (most-recent signal wins, so process in forward order and replace earlier duplicates)
2. Maintain a `seen: dict[str, int]` mapping `group_key → index of current survivor in output list`
3. For each signal, compute the group key:
   ```python
   entry_bucket = round(signal.entry_price / (signal.entry_price * 0.001)) * (signal.entry_price * 0.001)
   # Simpler: two signals are duplicate if abs(a.entry_price - b.entry_price) / a.entry_price < 0.001
   group_key = f"{signal.strategy.value}:{signal.direction.value}"
   ```
4. Dedup rule: two signals with the same `group_key` (same strategy + same direction) AND `abs(a.entry_price - b.entry_price) / a.entry_price < 0.001` are duplicates. The most-recent one (later in the list) survives; the earlier one is deduped.
5. For the 60-minute cooldown: since signals are produced per 15-min run (all signals in the input list are from the current run), treat the full input as within the cooldown window. Future phases can pass a filtered list if needed.
6. Log per deduped signal:
   ```python
   log.info("pipeline.dedup", strategy=sig.strategy.value, direction=sig.direction.value, entry=sig.entry_price)
   ```

Return the survivors list (Pydantic objects unchanged) and the deduped list. Do NOT mutate the input objects — callers track status externally.

**`src/pipeline/conflict_filter.py`**

Module-level logger: `log = structlog.get_logger(__name__)`

```python
def filter_conflicts(
    signals: list[CandidateSignal],
) -> tuple[list[CandidateSignal], list[CandidateSignal]]:
```

Returns `(kept, rejected)`.

Algorithm (CLAUDE.md §10.2):
1. Group signals by direction: `buys = [s for s in signals if s.direction == Direction.BUY]`, `sells = [s for s in signals if s.direction == Direction.SELL]`
2. Since this bot trades XAUUSD only (single instrument), any BUY + SELL combination is a conflict.
3. If both `buys` and `sells` are non-empty:
   - Best buy = max(buys, key=lambda s: s.confidence)
   - Best sell = max(sells, key=lambda s: s.confidence)
   - Winner = best_buy if best_buy.confidence >= best_sell.confidence else best_sell
   - All other signals (losers) go to `rejected`
   - Log: `log.info("pipeline.conflict_resolved", winner_direction=winner.direction.value, winner_confidence=winner.confidence, rejected_count=len(rejected))`
4. If only buys or only sells: all signals are `kept`, none `rejected`
5. Return (kept, rejected)
