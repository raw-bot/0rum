<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Phase 6 (publisher) → Phase 7 (subscriber) | `_alert_hooks` is module-global; Phase 7 registers its callable at app startup. No dynamic registration from request paths. |
| `_publish_alert` → individual hook | Each hook is awaited inside a try/except — a malicious or buggy hook cannot suppress alerts to other hooks or crash the breaker. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-02-01 | Repudiation | A failing hook silently swallows the alert | mitigate | `_publish_alert` logs `risk.alert_hook.failed` with `error=str(exc)` for every failure (structlog event observable in production logs); the breaker independently logs `risk.circuit_breaker.tripped` (Plan 06) so the trip itself is auditable even if every hook fails. |
| T-06-02-02 | Tampering | A registered hook mutates the alert DTO | mitigate | `CircuitBreakerAlert` uses `model_config = ConfigDict(frozen=True)` (Pydantic v2) — any hook attempting `alert.consecutive_stops = 0` raises `ValidationError`. |
| T-06-02-03 | DoS | A malicious hook intentionally raises to suppress alerts to subsequent hooks | mitigate | Per-hook try/except ensures the iteration ALWAYS visits every registered hook regardless of upstream failures. Test 2 in `test_hooks.py` enforces this. |
| T-06-02-04 | Elevation | A non-startup code path calls `register_alert_hook` to inject a hook | accept | `register_alert_hook` is a plain Python function with no auth gate. Phase 7 will own the registration call at startup; v1 trust model assumes `src/main.py` is the only registration site. ASVS L1 does not require runtime hook authentication for in-process pub-sub. |
| T-06-02-05 | Information Disclosure | `last_stop_trade_id: UUID` leaks internal IDs in logs | accept | UUIDs are opaque to downstream consumers; the hook list is in-process; structlog redaction (if needed) is a project-wide concern, not Phase 6. |

ASVS L1: this plan defines a trust boundary (publisher → subscriber) but no auth/session/crypto/input-validation surface. No high-severity threats.
</threat_model>
