# ADR-001: Use Sandbox Replay Before Building the 0rum System

## Status
Accepted

## Date
2026-05-28

## Context
The project contains a third-party one-shot prompt intended to scaffold and deploy a self-improving 0rum trading agent. The prompt asks an agent to run commands, open URLs, install dependencies, deploy to Railway, install 0rum, and hand off a recurring strategy-reflection loop.

The goal is to test the prompt with minimal behavioral changes while avoiding unsafe access to the operator's real home directory, secrets, wallets, SSH keys, or live exchange permissions.

## Decision
Run the original prompt through a sandbox-replay process before extracting any durable system from it.

The original prompt remains immutable. The first execution uses a disposable HOME, no real exchange keys, paper mode only, a Railway test project, and manual command approval. The output generated by the prompt is treated as a prototype artifact. It is audited before any durable 0rum automation is enabled.

0rum must not be installed globally during the first replay. 0rum should later run in Docker or on a dedicated VPS with explicit cron, read-only first-week behavior, and manual promotion of strategy changes.

## Alternatives Considered

### Modify the one-shot prompt directly
- Pros: Quick path to a safer text.
- Cons: Risks introducing new errors, diverging from what needs to be tested, and obscuring which behavior came from the original prompt.
- Rejected: The user wants to test the one-shot prompt without major prompt edits.

### Execute the one-shot prompt directly on the host
- Pros: Closest to the video workflow.
- Cons: Gives an agent too much access to the real machine and environment.
- Rejected: The prompt performs installs, deployments, and file writes.

### Let a secondary model rebuild the system from scratch
- Pros: Can produce cleaner code.
- Cons: Stops testing the original one-shot behavior and moves too much trust into a new generation step.
- Rejected for the first pass. A secondary model can help after extraction.

## Consequences
- The first pass tests the original prompt's behavior without trusting it with the real environment.
- The replay may expose places where the one-shot assumes a real home directory or global installs.
- Railway deployment must target a disposable project.
- After the replay, the generated worker code must pass a manual audit before any recurring 0rum process is attached.
